# Подключаем GitHub — Git, gh и два логина

> Делаем это **после** того, как Claude Code установлен и работает: ставить всё будет сам агент, так что сначала нужен он.
> Инструкция одинаковая для Windows, macOS и Linux — в этом и фокус.

---

## Зачем это нужно прямо сейчас

Сайт ты уже собрал. Но живёт он только у тебя на компьютере — как рисунок в столе. Чтобы вынести его в интернет (это мы сделаем на занятии 2), нужны две вещи: **Git** и связь с **GitHub**. Поставим их сегодня, пока руки в масле.

Но есть причина поважнее, и она касается всех, у кого **Windows**.

Claude Code выполняет команды через специальный инструмент. Если в системе стоит Git, агент пользуется **Bash** — тем же самым, что у преподавателя на экране. Если Git не стоит, на Windows агент переключается на **PowerShell** — другой язык команд. Всё вроде работает, но выглядит иначе, чем на демонстрации, и советы «сделай как на экране» начинают промахиваться.

Поэтому Git на Windows — это не «пригодится потом», а **«чтобы у тебя было то же, что у всех»**. Ставим сразу.

---

## Шаг 1. Просим агента всё поставить

Тут и происходит главное волшебство курса. У всех разные компьютеры: Windows, macOS, Linux — и в каждой системе программы ставятся по-своему. Разбираться в этих различиях тебе **не нужно**. Агент сам посмотрит, какая у тебя система, и подберёт правильный способ.

Отправь Claude Code этот промпт:

```text
Проверь, установлены ли у меня git и GitHub CLI (gh).
Если чего-то нет — определи мою операционную систему
и установи подходящим для неё способом.
Потом покажи версии обеих программ.
```

Агент посмотрит, что уже есть, скачает недостающее и отчитается версиями. Возможно, система спросит пароль администратора — это нормально, так устанавливаются программы.

> 💡 **Что вообще за две программы?**
> **Git** — сама система сохранений и версий, работает у тебя на компьютере.
> **gh** (GitHub CLI) — «переговорщик» с сайтом GitHub: через него агент сможет создавать репозитории и отправлять туда твой код.

**Если агент не справился** — не паникуй, это бывает (нет прав администратора, антивирус, рабочий ноутбук с ограничениями). Спустись в раздел «Если не получилось» внизу страницы, там ручной путь.

## Шаг 2. Два логина — и почему их именно два

Теперь надо представиться GitHub'у. И тут студенты обычно путаются, так что разберём сразу.

Логиниться нужно **дважды**, в двух разных местах. Это не ошибка и не дублирование: у редактора и у агента — **разные связки ключей**. Один вход другой не заменяет.

| Где логинимся | Кто этим пользуется | Что это даёт |
|---|---|---|
| **VS Code** → Accounts → Sign in with GitHub | Сам редактор | Значки и панели GitHub в интерфейсе, синхронизация настроек |
| **`gh auth login`** в терминале | Claude Code (агент) | Создавать репозитории и отправлять код — всё, что агент делает руками |

Аналогия: у тебя есть ключ от кабинета и ключ от сейфа. Оба твои, но открывают разное.

### 2а. Логин для агента

Попроси Claude Code:

```text
Запусти gh auth login, чтобы я авторизовался на GitHub.
После авторизации настрой git на работу с GitHub через gh.
```

Дальше отвечаешь на вопросы мастера — выбирай **GitHub.com**, протокол **HTTPS**, вход **через браузер**. Откроется браузер, там подтверждаешь — и всё.

> ⚠️ Второй командой агент выполнит `gh auth setup-git`. Она незаметная, но важная: без неё при отправке кода GitHub начнёт клянчить пароль. Не пропускай.

### 2б. Логин для редактора

Здесь всё руками, это пара кликов:

1. В VS Code слева внизу, на самом краю панели — **иконка человечка** (Accounts)
2. Нажимаешь → **Sign in with GitHub**
3. Открывается браузер → **Authorize** → готово

## Шаг 3. Проверяем, что всё встало

Не верь на слово — проверь. Отправь агенту:

```text
Покажи версии git и gh, а также мой текущий статус авторизации на GitHub.
```

Ты должен увидеть примерно такое:

```
git version 2.51.0
gh version 2.89.0
✓ Logged in to github.com account твой-ник
```

Видишь свой ник в последней строке — **всё готово**, на занятии 2 сайт уедет в интернет без единой заминки.

> 🔄 **Команда «не найдена», хотя только что ставили?** Классика. Система узнаёт о новых программах не сразу — **перезапусти VS Code** целиком и проверь ещё раз. На Windows после установки Git перезапуск обязателен: именно в этот момент агент подхватывает Bash.

## Если не получилось — ставим руками

Агент справляется почти всегда, но если уж нет — вот ручной путь. Открой раздел своей системы.

<details>
<summary><b>🪟 Windows</b></summary>

В PowerShell:

```powershell
winget install --id Git.Git -e
winget install --id GitHub.cli -e
```

**Нет команды `winget`?** Такое бывает на старых сборках Windows. Тогда скачай обычные установщики и запусти их как любую программу:
- Git: [git-scm.com/downloads/win](https://git-scm.com/downloads/win)
- GitHub CLI: [cli.github.com](https://cli.github.com)

При установке Git все галочки можно оставить по умолчанию — просто жми «Далее».

</details>

<details>
<summary><b>🍎 macOS</b></summary>

```bash
xcode-select --install     # Git (откроется окно установки от Apple)
brew install gh            # GitHub CLI
```

**Нет Homebrew?** Не беда, качай установщик GitHub CLI с [cli.github.com](https://cli.github.com) — обычный `.pkg`, ставится двойным кликом.

</details>

<details>
<summary><b>🐧 Linux (Ubuntu / Debian)</b></summary>

Git ставится просто:

```bash
sudo apt install git
```

А вот `gh` в стандартных репозиториях **отсутствует** — нужно сначала подключить официальный репозиторий GitHub, там несколько команд с ключами. Не переписывай их вручную: возьми актуальную инструкцию по ссылке — [официальная инструкция GitHub CLI для Linux](https://github.com/cli/cli/blob/trunk/docs/install_linux.md) — или просто отдай эту ссылку агенту и попроси сделать по ней.

</details>

## Частые затыки

**«Нужен пароль администратора, а у меня рабочий ноутбук»**
На корпоративных машинах установка часто закрыта. Вариант: поставить программы «для пользователя» (GUI-установщики так умеют) либо попросить админа. Если совсем никак — скажи преподавателю, разберём отдельно.

**«Антивирус ругается на установку»**
Бывает с новыми `.exe`. Скачивай только с официальных адресов, указанных выше, и разреши установку в антивирусе.

**«Всё поставилось, но команды не работают»**
Перезапусти VS Code. Если не помогло — перезагрузи компьютер: система обновит список программ.

**«gh auth login запутал вопросами»**
Ответы для нашего курса: **GitHub.com** → **HTTPS** → **Yes** (авторизовать Git) → **Login with a web browser**. Если сбился, ничего страшного — запусти команду заново.

Инструмент готов. На занятии 2 разберём, **как** всё это устроено (main, ветка, push, origin), и выложим твою страницу в интернет — с живой ссылкой, которую можно скинуть друзьям.
